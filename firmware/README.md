# SmartRide OBU firmware

ESP32-S3 firmware for the on-board unit (Arduino core 2.0.17 + NimBLE-Arduino 2.x, built with PlatformIO).

**v0.1 status:** the BLE service, ride statistics, crash state machine and ride-log transfer are
the real code. The **GNSS and IMU are simulated** (`src/sim_sensors.*`) until the ATGM336H-5N and
MPU6500 are fitted. Every LIVE packet carries a `SIMULATED` flag so the app can say so.

## Build, flash, test

```bash
pio run                                   # build (default env: esp32-s3)
pio run -t upload -t monitor              # flash + serial console
pio run -e esp32dev                       # classic ESP32-WROOM-32 build
pio test -e esp32-s3                      # 14 unit tests, run ON the board (Unity)
```

`pio` is `%USERPROFILE%\.platformio\penv\Scripts\pio.exe` if it isn't on PATH. On Windows, set
`PYTHONIOENCODING=utf-8` so PlatformIO's tree output doesn't crash the console.

## Layout

```
include/protocol.h        BLE contract: UUIDs, opcodes, packed structs (mirrors docs/ble-protocol.md)
lib/core/src/             hardware-independent logic (unit-tested)
  config.h                thresholds and rates; (report) = from Phase 1, (tune) = set from trials
  types.h                 GnssFix, ImuSample, Command
  geo.*                   ellipsoidal local-projection distance (float, FPU) -- replaces Haversine
  ride_stats.*            plausibility gate, distance/duration/speed
  route_simplifier.*      online sliding-window Douglas-Peucker for stored routes
  battery.*               Li-ion voltage -> state of charge
  crash_detector.*        impact -> sustained tilt -> stillness state machine     (report eq. 5-9)
  ride_log.*              RideSession (stats + simplified route) + LogStore (RAM stub)
src/
  main.cpp                FreeRTOS tasks: gnss, imu, ride, crash, ble  + serial console, LED, BOOT button
  ble_service.*           NimBLE GATT server + Device Information service
  sim_sensors.*           STUB GNSS (route replay with injected faults), IMU (riding/pothole/crash), battery
  sim_route.h             GENERATED by tools/gen_sim_route.py (TKMIT -> Ezhukone loop, 1501 fixes)
  canned_rides.*          STUB: 3 past rides so log sync has data on first boot
test/test_core/           on-target Unity tests for lib/core
```

## Task layout (Phase 1 report, "Data Processing Flow within the ESP32-S3")

```
gnss_task (1 Hz)  --fix queue-->     ride_task  --notify-->  ble_task --> LIVE notify
imu_task (100 Hz) --motion queue-->  crash_task --events-->  ble_task --> CRASH notify
                                     ble_task <-- command queue <-- CONTROL write / serial / BOOT
                                     ble_task --> LOG frames (list / get / ack)
```

All application tasks run on core 1. The NimBLE host runs on core 0. BLE callbacks only queue
work and never do it themselves.

## Serial console (115200 baud)

| Key | Action |
|---|---|
| `h` | help |
| `i` | info: BLE state, clock, free heap, IMU overruns |
| `l` | list ride logs on the device |
| `s` / `x` | start / stop ride (a stopped ride becomes a log) |
| `c` | simulate crash → IMPACT → TILT → CONFIRMED in about 4 s |
| `p` | simulate pothole → IMPACT → IDLE (rejected after 5 s) |
| `k` | cancel crash alert |

**BOOT button:** simulate a crash, or cancel when an alert is pending.
**RGB LED** (GPIO48): blue blink = advertising, green = phone connected, fast red = crash pending.

Things to point at in the serial log during a demo:
- `[GNSS] REJECTED outlier: 445 m jump in 1 s` — the plausibility gate. An outlier is injected every 97 fixes.
- `[GNSS] no fix` — distance pauses while crash detection carries on. A dropout is injected every 211 fixes.
- `[CRASH] -> IDLE (rejected: impact without sustained tilt)` — a pothole is not reported as a crash.

## Testing without the app

`tools/ble_client.py` is a complete protocol client for a laptop with Bluetooth:

```bash
python -m venv tools/.venv && tools/.venv/Scripts/pip install -r tools/requirements.txt
tools/.venv/Scripts/python tools/ble_client.py info     # device info + one LIVE/CRASH read
tools/.venv/Scripts/python tools/ble_client.py live     # stream LIVE + CRASH
tools/.venv/Scripts/python tools/ble_client.py logs     # LIST + GET all, verify seq + CRC
tools/.venv/Scripts/python tools/ble_client.py crash    # SIM_CRASH -> CONFIRMED -> CANCEL
```

On a phone, **nRF Connect** shows the service, characteristic names and raw values.

## Replacing the stubs (Phase 3)

| Stub | Replace with | What must not change |
|---|---|---|
| `SimGnss::next()` | ATGM336H-5N driver: UART2 NMEA (RMC + GGA) parser, checksum, 1 PPS on a GPIO | emits `GnssFix` into `qFix` at 1 Hz |
| `SimImu::sample()` | MPU6500 driver: FIFO burst read, scale to g, bias removal | emits `ImuSample` into `qMotion` at 100 Hz |
| `LogStore` (RAM) | LittleFS with framed, CRC'd records (power-loss safe) | `add / find / remove / all` |
| `LIVE_SIMULATED` flag | clear it once real sensors report | — |
| `cfg::IMPACT_G`, `TILT_*`, `STILL_*` | values from the drop, tilt and road trials | — |
